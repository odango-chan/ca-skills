# Skill-owned Python Script Contract vNext

**Status:** Normative vNext source contract. This is a breaking replacement for the v0.2 Script input model.

## 1. Identity and entry point

A Script is a Python source file owned by exactly one Skill:
`skills/<skill-name>/scripts/<relative-path>.py`.

Its only identity is Skill name plus package-relative path. It does not declare a Tool ID, Operation ID, Capability ID or version in Python comments.

The only supported entry point is:

```python
def main(input: dict) -> OutputType:
    ...
```

- The parameter is named `input` and annotated exactly `dict`.
- The return annotation names a non-empty `TypedDict` declared in the same file.
- No alternate entry points, extra parameters, `**kwargs` or untyped return values.

## 2. Input is derived from the exact invocation

Scripts do not author their own Input Schema. Compiler derives a closed input projection for each call site.

### Procedure Script

For `script: scripts/foo.py`, the keys in that node/step's `with:` object form the Script business input. Every `from:` resolves to an exact Producer Schema and must be available on every path reaching the call. Every `value:` is a JSON literal checked against the inferred consumer type.

The call-site map is also the Script's input contract: pass only fields the Script actually consumes. Do not forward an entire Producer object or Procedure input for convenience. The proposed `with.from: input` shorthand is not supported for Scripts because no independent declared Script input-name contract exists from which the Compiler could safely select fields. Do not infer a Script interface from dynamic Python behavior.

Two calls to the same Script may have different input projections. `input: dict` does not authorize arbitrary field access.

### Predicate Script

For `evaluator: {type: script, ref: scripts/foo.py}`, the Script receives:

- `input.<name>`: each named business parameter declared by that Predicate and supplied by the corresponding Procedure `verify.arguments` position;
- `input.evidence.<name>.refs`: Host-attached source-fact references for the corresponding producer-backed input.

The reserved `evidence` property is generated by Host/Runtime. Skill bindings cannot create, overwrite or widen it. Evidence is not a business payload and does not replace the input's Owner Schema.

The Script cannot acquire data, call an Observation source, perform another READ, or make a network request. Missing input or invalid Evidence is handled by Runtime as UNKNOWN before a definite Predicate verdict.

## 3. Output Schema

A Script declares only the structure of the value it computes. Compiler generates a read-only JSON Schema Draft 2020-12 from the return `TypedDict`.

Supported static forms:

- `str`, `int`, `float`, `bool`;
- nested `TypedDict` declarations in the same file;
- functional `TypedDict("Name", {...})` for JSON keys that are not Python identifiers (for example, `5qi`);
- `list[T]`, `Literal[...]`, `NotRequired[T]`;
- `Annotated[T, {<literal JSON Schema constraints>}]`.

Supported literal constraints: string `minLength`, `maxLength`, `pattern`; numeric `minimum`, `maximum`; array `minItems`, `maxItems`, `uniqueItems`.

Output rules:

- Output must be a non-empty, fully declared `TypedDict`; generated `additionalProperties` is `false`.
- Required/optional fields and Literal values are preserved exactly.
- `dict`, `Any`, `object`, empty output types, broad/dynamic unions and inferred function-body schemas are forbidden.
- Compiler never executes Python or infers types from function bodies.
- Generated Output Schemas are BuildResult outputs, never author source or Compiler inputs.
- No generated Script Input Schema is produced.

If a Script merely forwards an existing Producer value, use a direct binding instead.

## 4. No metadata or per-Script execution policy

The old `# /// connectionagent-tool` block is not part of vNext. Do not declare `inputSchema`, `outputSchema`, `effect`, sandbox permissions, timeout, local Tool names or Operation IDs in Python comments.

Scripts are deterministic local computation only. They must not access network/MCP/HTTP, shell/subprocess, filesystem, environment secrets, clocks, random sources, databases or credentials. Host owns sandbox and timeout policy.

A Script is a Skill-owned source asset, not an independently invocable Tool or Capability. There is no `allowedResources.localTools`.

## 5. 5GC migration examples

The existing 5GC Scripts remain the business calculation reference:

- `select_establishment_configuration.py`
- `build_pcf_policy_inputs.py`
- `build_n1n2_delivery.py`
- `evaluate_udm_read.py`
- `evaluate_transfer_start.py`

Their input projections are migrated to explicit call-site bindings / Predicate parameters. Their output TypedDicts remain the output authority. No compatibility wrapper or duplicate authored Input Schema is retained.
